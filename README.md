## Лабораторная работа 10. Генерация изображения веб-сервером по запросу
Реализуйте веб-приложение со следующими маршрутами (роутами):
Маршрут /login
⎯ Метод: GET
⎯ Ответ: JSON {"author": "ваш_логин_в_moodle"}
Маршрут /makeimage (основная логика)
⎯ Поддерживает два метода:
▪ GET – возвращает HTML-страницу с формой (поля: width, height, text).
▪ POST – принимает данные из формы, генерирует изображение и
возвращает его как готовый JPG-файл (Content-Type: image/jpeg).
⎯ Параметры (из form-data или x-www-form-urlencoded):
▪ width – целое число, пиксели (допустимый диапазон, например, 10–
2000)
▪ height – целое число, пиксели
▪ text – строка (будет нарисована на изображении, шрифт по умолчанию)
⎯ Валидация:
▪ Если width или height не являются положительными целыми числами
(или выходят за разумные пределы) – вернуть ту же страницу с формой и показать
сообщение: message: "Invalid image size"
⎯ При успехе:
▪ Создаётся изображение заданного размера, заливается цветом
(например, светло-серым), на нём рисуется переданный text (по центру).
▪ Возвращается HTTP-ответ с заголовком Content-Type: image/jpeg и
бинарными данными JPEG.
▪ Никакого base64, никакой отдельной страницы – браузер сам
покажет картинку или встроит её как обычное изображение.
Страница с формой (GET /makeimage) должна:
⎯ Содержать form с method="POST" и enctype="application/x-www-form-
urlencoded".
⎯ Иметь поля width, height, text и кнопку отправки.
⎯ При наличии сообщения об ошибке (из предыдущего POST) – отображать его
красным цветом.
Дополнительные задания (усложнения)
Эти пункты не обязательны, но повышают шанс на получение высокой оценки. Вы можете
выбрать один или несколько пунктов.
1. Полиглот – реализовать один из маршрутов на другом фреймворке
(Node.js/Express, Django, Go) и проксировать запросы через Flask (или сделать отдельный
микросервис).
Например:
⎯ /makeimage на Flask, а /makeimage_alt на Express.
2. Фронтенд-фреймворк – вместо обычной HTML-формы использовать
React/Vue/Svelte. Отправка данных через fetch, рендеринг полученного изображения на
той же странице (без перезагрузки).
⎯ При успехе – показывать миниатюру (thumbnail).
⎯ При ошибке – выводить сообщение без перезагрузки.
3. Чистый бэкенд (API only) – убрать HTML-форму полностью.
⎯ /makeimage принимает параметры через GET или POST (JSON) и возвращает
изображение или base64.
⎯ Проверка через Postman/curl.
⎯ Добавить CORS-заголовки (Access-Control-Allow-Origin: *).
⎯ Предусмотреть отдельный маршрут /health для проверки.
4. Асинхронный thumbnail – на той же странице с формой показывать
предварительный просмотр изображения (100x100) сразу после ввода данных, без нажатия
кнопки (debounce + fetch)
